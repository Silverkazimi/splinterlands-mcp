# DEC staking observations — 2026-09-07

This note records live observations made from this repository on 2026-09-07. The durable request records are in `tests/evidence/land-result-contract-evidence.json`; the five response fixtures are the scalar overall response, eleven decstaked rows, an empty decstaked array, the resolved region object, and the pending-claim object.

The four observed routes are `GET /land/stake/dec/overall`, `GET /land/stake/decstaked`, `GET /land/stake/dec/region`, and `GET /land/stake/evp/pending-claim`. Each returned HTTP 200 with `application/json; charset=utf-8` on the measured calls. The overall response was `{"status":"success","data":<number>}` with a bare numeric `data` value. The decstaked response was an array of rows with `id`, `region_uid`, `player`, `amount`, `percent_claimable`, `last_trx`, `created_date`, and `last_updated_date`; every numeric field observed was a JSON number. The pending-claim response was an object with `pending_claim_amount` as a JSON number.

The region route changes the JSON type of `data`. A resolved request returned an object with `uid`, `dec_stake_needed`, `dec_staked`, and `dec_stake_in_use`; a valid region where the account held no stake returned the same full object shape with zero figures. Requests missing `region_uid`, missing `player`, or containing no parameters returned `{"status":"success","data":[]}`. Thus an empty array on this route means the request was incomplete in the observations here, while a genuinely empty position is represented by zero figures inside a full object. The shared empty-result short-circuit accepts the empty-array branch before the object fingerprint is compared, so one declarative contract covers both response shapes.

Fifteen requests were recorded. Overall was called with an account, without parameters, and with a syntactically valid name matching no account. Decstaked was called with an account, with that non-existent name, and without parameters. Region was called with an account and one held region, the same account and a second region, the account and a valid region with no stake, the account without `region_uid`, without parameters, and with the region uid but no player. Pending-claim was called with an account, with the non-existent name, and without parameters. The unparameterized calls returned plausible zero or empty answers rather than errors, and the non-existent-name calls returned answers indistinguishable from the corresponding empty-account cases.

The declared-required `player` parameter was accepted when omitted on all four routes, and `region_uid` was accepted when omitted on the region route. The catalogue records those six parameters as `measuredRequired: false`, describing upstream acceptance. The registered tools refuse calls without the account, and the region tool also refuses calls without the region uid, because the upstream's unscoped answers do not identify an account or region. The advertised schemas remain optional because they are derived from the catalogue measurement.

The overall figure equalled the sum of the eleven decstaked amounts in one account capture, and the two observed region figures matched that account's corresponding decstaked rows at that instant. This is an observation of one account at one instant, not a durable identity or a scope proof. No tool adds, compares, or derives any of these figures.

The pending-claim route returned zero for both a real account and a name matching no account, while the real account's pending amount was also zero. Whether those cases can be distinguished is untested rather than disproved. No claim is made here about what EVP is, what makes an amount claimable, or what any of the figures mean.

No 200-wrapped `AppException` body appeared in these fifteen calls. That count does not establish that the family is free of the hazard. A VAPI envelope carrying `status` without `data` would also be classified as an empty result by the shared definition; this row does not change that shared definition.
