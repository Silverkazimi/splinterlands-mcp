## Measured selectors and limits

The unfiltered guild list exceeded 2 MiB and the capture stopped after reading the sentinel byte. A name taken from the public guild profile returned one guild; an unmatched synthetic name returned an empty guilds list with num_actionable_mail=0. The tool requires a name, preserving the transport cap. Broad name filters may still exceed it.

Find by id returned 6679 bytes; ext=true returned 2101 bytes and omitted default extra fields. The contract covers common fields without assuming ext=true expands details. data, buildings and tournament_data are JSON-encoded strings, unlike nested objects in the player-profile representation.

Members without status returned 230 rows; status=active returned 30. The same active call with undocumented limit=2 and offset=2 returned the identical 30 rows; those observed-only inert inputs are not exposed. Contributions without type returned empty. guild_hall and arena each returned 50 rows; the captured building types contributed to the contract. No working contribution pagination is established.

Brawl records with guild_id returned a results array. cycle=383 selected one row; start_cycle=382 and end_cycle=383 returned those two cycles. SPS payout fields are decimal strings. Other declared tournament/date selectors have not all been proven effective.

Brawl SPS rewards with include_total=true and include_cycles=true returned {}. String 1 selected the requested sections: include_total alone returned a number, include_cycles with cycle returned its row array, and both returned both sections. The global total was 62864011.077 while the selected cycle payout was 153207.923. The server does not label the global total as a selected-cycle or guild sum. Each section is optional, but an empty or malformed response is not treated as reward data.

Fixtures retain three root or named-list rows and all surrounding fields. Result bounds remain 100 rows and 256 KiB; all quantities and encoded strings remain unchanged.
